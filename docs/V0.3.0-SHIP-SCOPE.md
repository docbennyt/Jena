# Jena v0.3.0 Ship Scope

This file is the working contract for the v0.3.0 release. Until v0.3.0 is verified, Jena work must stay inside this scope.

## Objective

Ship a reliable local core for Windows 11:

- correct disk and storage accounting
- configurable target free space
- deterministic reclaim plan
- user-selected Project Library discovery
- persistent project state: Active, Inactive, Never Archive, Archived
- Downloads cleanup through the Windows Recycle Bin
- verified project ZIP archiving with safe dependency exclusions
- tested restore from archive

## Required User Flows

### Home: I need space

Jena opens with the drive state, configured target free space, the remaining gap, and ranked opportunities. The primary workflow is building a recovery plan. The plan is informational until the user approves individual actions.

### Downloads: Deal with the mess

Downloads are grouped into Installers, Archives, Images, Documents, Videos, and Other. Selected disposable items can be moved to the Windows Recycle Bin after one confirmation. Jena must explain size, age, location, and suggested action for reviewable files.

### Projects: What am I actually working on?

The user chooses a Project Library root. Jena discovers real project roots only, avoids dependency/cache false positives, calculates project size, and persists project state across restart.

### Project: Archive this safely

Inactive projects can be archived to a ZIP. Regenerable dependency/cache folders are excluded by default. Jena writes a manifest, closes the ZIP, reopens it, validates member hashes, and only then performs the chosen post-archive action. The safe default is moving the original project to the Windows Recycle Bin.

### Archive: Bring it back

Restore extracts into a staging area first, verifies restored file hashes against the manifest, and only then places the project into the requested destination. Existing destinations are never overwritten automatically.

### Storage: Where did my disk go?

Storage inspection remains a deeper page. It must connect information to safe actions such as opening the folder, cleaning dependencies, archiving a project, or recycling selected Downloads.

## Explicitly Frozen Until After v0.3.0

The following ideas belong in `docs/ROADMAP.md`, not in v0.3.0 implementation:

- cloud providers
- MCP integrations
- AI chat
- filesystem watchers
- automatic permanent deletion
- installer monitoring
- new full-page Organize or Automation experiences
- further visual redesign beyond what is needed for correctness and usability

## Verification Bar

The release is not done when source tests pass. A verified v0.3.0 build must provide evidence for:

- exact automated test result
- project-detection fixture result
- archive verification result
- restore hash/equality result
- Recycle Bin test result
- persistence-after-restart result
- packaged `Jena.exe` smoke/integration result
- fresh portable ZIP extraction and integration result
- current commit SHA, when a Git repository is available
- final portable build location and SHA-256

If a requested flow does not work in the packaged application, it is not done.
