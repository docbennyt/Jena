# Jena v0.3.2 Compression Verification

> Historical verification record. The archive-content tree verified here may remain as a bounded archive/recovery aid, but ADR-002 supersedes any interpretation of it as a strategic Workspace Browser or Explorer replacement.

This document records the required evidence for the 7-Zip `CompressionService` integration. It must be updated from actual packaged-app runs before release.

## Safety Contract

- Jena decides project eligibility and exclusions.
- Active and Never Archive projects are not archive recommendations.
- No project is archived automatically.
- The original project reaches the Windows Recycle Bin only after integrity and SHA-256 verification succeed.
- Restore extracts to staging, verifies hashes, and refuses destination collisions.
- Archive paths are validated before extraction and existing files are never overwritten.

## Source Verification

- Full test suite: `52 passed in 14.43s` during the final release pipeline.
- Compile validation: passed.
- Source UI responsiveness fixture: responsive with 20,000 filesystem entries and five archive-tree nodes.
- Review found and fixed two archive regressions before release: Archived rows disappearing after source recycling, and ZIP/7z sidecar manifest-name collisions.

## Benchmark

- Engine: 7-Zip 26.03, the exact vendored runtime.
- Profile: balanced (`-mx=5`, multithreaded).
- Method: three timed runs per fixture and format; medians used.
- Input: 13,801,814 bytes across three representative source-code fixtures.
- ZIP: 6,937,132 bytes, 0.8339 seconds.
- 7z: 6,447,031 bytes, 1.5170 seconds.
- Result: 7z was 7.06% smaller and 1.82 times slower overall.
- Default: ZIP for native Windows recovery compatibility.
- Compact option: 7z.
